Validate a synthetic 837P using plain HTTPS. The API is public and requires no credentials.

OpenAPI specification · Plain-text API index

Run your first test

Download a passing example, then send its original bytes to POST /api/v1/validate with Content-Type: application/edi-x12.

curl --fail-with-body -sS -o accepted.837 \
  https://claimlab.opensoft.dev/api/v1/examples/accepted.837

curl --fail-with-body -sS \
  -H "Content-Type: application/edi-x12" \
  --data-binary @accepted.837 \
  https://claimlab.opensoft.dev/api/v1/validate

Send raw ASCII X12, up to 1 MiB. Use fictional subscribers and set ISA15=T. Keep real patient information and payer credentials out of uploads.

Read the result

HTTP 200 means the simulation ran. Treat a file as passing when simulated and accepted are both true. ClaimLab results are simulations. Payer acceptance requires a separate enrolled test.

  • TA1 in interchange_ack reports envelope failures. A passing interchange normally returns not_generated at this stage.
  • 999 in file_ack reports transaction structure problems. If it is rejected, claim checks are skipped.
  • 277CA in claim_ack reports individual claim results. If the batch is mixed, inspect claims for the one-based claim number, status, and issue codes.

For request errors, check the HTTP status and error.code. 400 means the body was empty, 413 means the upload was too large, and 415 means the media type was unsupported.

Check a known failure

  • Interchange mismatch returns a rejected TA1 with code 001.
  • Missing claim total returns a rejected 999.
  • Unbalanced charge returns an accepted 999 and a rejected 277CA.
